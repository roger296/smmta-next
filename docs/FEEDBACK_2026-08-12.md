# Big Bakes Stock — 12 August 2026 live-test feedback and defect register

The South London venue ran a live test of Big Bakes Stock on **12 August 2026**
using an in-venue **iPad** and a **laptop**. Everything below is the raw tester
feedback plus the traced root causes. Defect IDs (A-1 … F-8) are the checklist
the August fix set (prompts F1 … F15) closes out against; F15 re-asserts every
one of them with a named regression test.

> Source documents: `Stock System Feedback August 12th.pdf` (the raw feedback)
> and `Big Bakes Stock — Aug 12 Feedback: Bug Register & Correction Plan.md`
> (the traced root causes). This file is the in-repo copy so the register
> travels with the code.

---

## A — Saved work, sync and feedback

| ID | Tester report | Root cause |
|---|---|---|
| A-1 | Submissions reported as "Saved offline — will sync" even when the server rejected them | `submitOrQueue` (`apps/web/src/lib/offline-submit.ts`) had a bare `catch {}` that queued **every** failure, including HTTP 4xx rejections |
| A-2 | Queued work never reached the server | `flushPwaQueue()` had **zero production call sites** — nothing ever replayed the queue |
| A-3 | The sync pill never showed pending work | `SyncPill` was driven from `mutation.isPending`, so its `pending` / `offline` branches were dead code |
| A-4 | No way to answer "did my count actually go in?" | No queue inspection surface at all |
| A-5 | "Lack of visual feedback on screen exits leaves users uncertain whether inputs are saved, deleted, or processed" | Goods In cleared its line list on submit with only a transient toast |
| A-6 | A failed barcode lookup silently did nothing | `addByCode` did not catch lookup failures |

## B — Layout, chrome and legibility

| ID | Tester report | Root cause |
|---|---|---|
| B-1 | "Screen formatting cuts off the top of the page rendering any initial line inputs invisible and uneditable" (both orientations) | `.touch-app` is `position: fixed; inset: 0` but rendered **inside** the `_authed` desktop shell; sizing used `100vh`, and nothing tracked `window.visualViewport`, so the iOS keyboard scrolled the fixed overlay off the glass |
| B-2 | Keyboard opened on load and pushed the page up | `autoFocus` on the goods-in barcode input |
| B-3 | Background page scrolled underneath the venue screens | No body scroll lock / `overscroll-behavior` |
| B-4 | Venue screens were drawn over an admin page nobody could see | `/pwa/*` lived under the desktop `_authed` layout (sidebar + header + `<main class="p-6">`) |
| B-5 | Venue name missing from several screens | `TouchTopbar` took no venue prop; the stock-take start and consumption setup screens showed none |
| B-6 | Desktop venue-name selector unreadable | `SelectTrigger` sets a white background but inherits the navy header's light foreground |
| B-7 | "Page transitions feel quite abrupt; retaining a collapsible side menu might improve navigation confidence and confirm the active page" | Venue screens have no navigation context; the desktop sidebar does not collapse |

## C — Products, units and cost

| ID | Tester report | Root cause |
|---|---|---|
| C-1 | "Icing sugar displayed an incorrect default unit quantity of 1kg" | Ingredients seeded with `stockUom: 'g'`, `purchaseUom` NULL and `purchaseToStockFactor` `'1'`, so a 25 kg sack rendered `= 1 g` |
| C-2 | "Skittles displayed an incorrect base unit, preventing the 1.6kg bags from being added" | Same missing purchase-unit model |
| C-3 | "Manual barcode entry failed to find the product for an icing sugar delivery" | The product search predicate covered `name`, `stockCode` and `ean` but **not** `barcode`, despite the column and its index existing |
| C-4 | Costs displayed as £0.00 | `products.expected_next_cost` was `decimal(18,2)`; ingredients are priced at ~£0.0012/g |
| C-5 | Could not set a price from the venue screen | The "Set £" sheet could not write back `expectedNextCost` |
| C-6 | "Request to add base-unit increment buttons (e.g. auto-filling to 25kg and adding +25kg per click)" | Enhancement — no pack-step controls existed |

## D — Counting and number entry

| ID | Tester report | Root cause |
|---|---|---|
| D-1 | Stock-take rows read as raw alphanumeric strings, so not a single count could be logged | `useProductMap` requested `/products?pageSize=500`; `paginationSchema` caps `pageSize` at 250, so the request 400d, the query errored, and each row fell back to `productId.slice(0, 8)` |
| D-1b | The count screen depends on a second, larger, fallible request just to know what it is asking someone to count | `POST /stock-takes` returned bare `stock_take_lines` rows with no product identity |
| D-2 | Counts silently rounded to the nearest 100 stock units (4 kg → 0; 250 g → 300) | `bucketCount` in `apps/web/src/lib/uom.ts` had a blanket `quantum = 100` default. **Masked by D-1** — with no product map the UoM fell back to `each`, which is discrete and never bucketed |
| D-3 | Search on the count screen did not find items | Search matched only the (missing) product name; not `stockCode` |
| D-4 | "Default numbers are not overridden when typing (entering '3' into a default field of '1' results in '13')" | `KeypadSheet` seeded its buffer with `String(initial)`, so the first keypress appended |
| D-5 | "Request to enable direct number pad typing on laptop keyboards" | No `keydown` handling anywhere in the keypad sheets |

## E — Site binding, PWA entry and permissions

| ID | Tester report | Root cause |
|---|---|---|
| E-1 | "Accidental booking logged 100kg to Birmingham" from a South London device | `POST /auth/pin-login` returns the device's `siteId`, but `pin-login.tsx` discarded it; `SiteProvider` then defaulted to the first **active** site by `asc(sites.name)` — Birmingham |
| E-2 | "Adding the iPad PIN login page to the home screen redirects incorrectly to the standard email login page" | `manifest.webmanifest` `start_url: "/"`; `/` is under `_authed`, which redirects an unauthenticated visitor to `/login` |
| E-3 | "Requested an undo timer" | No reversal path existed for a booked goods-in receipt |
| E-4 | "…or role-based permission locks" | No role guard beside `requireAuth` |
| E-5 | No confirmation of the destination venue before booking | Book-in committed straight from the line list |
| E-6 | Manifest locked to portrait | `orientation: "portrait"`; the venue uses both orientations |

## F — End of Bake and recipe data

| ID | Tester report | Root cause |
|---|---|---|
| F-1 | "'Table +' and 'Table -' buttons are reversed when switching to 'What's Left' mode" | `Table−` *increased* `remainingQty` while the plain `+`/`−` steppers were not inverted, so two controls on one row moved the same number in opposite directions |
| F-2 | "Toggling to 'What's Left' resets the counter to 0, but toggling back does not reset it back" | The mode toggle zeroed the figure being switched away from, destroying the expected pre-fill |
| F-3 | Request: show the live table count implied by the current quantity | The number between the table buttons rendered `covers` — the read-only session total |
| F-4 | "Displayed recipes are not part of our offering of course" | `scripts/seed-bakes.ts` seeds four invented demo cakes (retired in F13 — the menu is now imported) |
| F-5 | "Selecting Vegan or GF options for Battenburg failed to generate required ingredients" | Every seeded recipe line is `BASE`; the server-side `GF_*` / `VEGAN_*` variant machinery had nothing to act on |
| F-6 | "No bake logs were submitted due to incorrect recipe data" | A missing recipe produced a transient toast and an empty ingredient list, not a blocking state |
| F-7 | Request: show benches under the kilo figures (for interruption recovery) | The count was not shown under the quantity. **NB:** a bench and a table are the same thing — one team baking one cake, "bench" being the venue's word. The first fix read them as two units and added a per-site conversion ratio; corrected 20 Aug (migration 0045) |
| F-8 | Client/server type drift on consumption lines | `ConsumptionLineDraft` did not declare `entryMode` / `remainingQty`, which `POST /session-consumption` validates |

## Verbatim tester feedback (12 Aug 2026, South London — iPad + laptop)

**Goods In**
- Manual barcode entry failed to find the product for an icing sugar delivery.
- Icing sugar displayed an incorrect default unit quantity of 1kg.
- Skittles displayed an incorrect base unit, preventing the 1.6kg bags from being added.
- Request to add base-unit increment buttons (e.g. auto-filling to 25kg and adding +25kg per click).
- Request clear visual feedback upon booking rather than having items immediately clear from view.
- Accidental booking logged 100kg to Birmingham; requested an undo timer or role-based permission locks.

**Stock Take**
- Every row read as a raw alphanumeric string, so no count could be logged.
- Default numbers are not overridden when typing (entering "3" into a default field of "1" results in "13").
- Request to enable direct number pad typing on laptop keyboards.

**End of Bake**
- "Table +" and "Table -" buttons are reversed when switching to "What's Left" mode.
- Toggling to "What's Left" resets the counter to 0, but toggling back does not reset it back.
- Request to show benches under the kilo figures.
- Displayed recipes are not part of our offering of course.
- Selecting Vegan or GF options for Battenburg failed to generate required ingredients.
- No bake logs were submitted due to incorrect recipe data.

**General / layout**
- Screen formatting cuts off the top of the page rendering any initial line inputs invisible and uneditable.
- Adding the iPad PIN login page to the home screen redirects incorrectly to the standard email login page.
- Lack of visual feedback on screen exits leaves users uncertain whether inputs are saved, deleted, or processed.
- Page transitions feel quite abrupt; retaining a collapsible side menu might improve navigation confidence and confirm the active page.
- Dashboard layout is clean, organized.
